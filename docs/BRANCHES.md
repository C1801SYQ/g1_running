# 分支整理说明

GitHub 的发布基线统一为 `main`。训练、部署、视觉和文档改动在验证后都合并到这条
主线；实验分支只作为本地工作副本，不作为长期发布入口。

## 最终保留的分支

| 分支 | 用途 | 状态 |
|------|------|------|
| `main` | 唯一发布、部署和文档基线 | 保留 |

本次整理会删除 `origin` 上其余历史、实验和模型分支的分支引用。删除分支只删除远程
引用，不主动删除本地工作区文件、未提交改动或对象内容；如需继续实验，请从 `main`
重新创建短期分支。

## 发布边界

- 发布源码、配置、测试、脚本、策略元数据和 README；
- 不发布训练日志、checkpoint 输出目录、编译目录、备份目录、下载缓存、压缩包和机器运行日志；
- 不发布内部工作记录、个人工具配置或其他工作流痕迹；
- `policy.pt` 必须与同目录的 `config.yaml`、`deploy.yaml`、`source.txt` 一起核对；
- 真实机器人验证仍需吊装、急停可触及，并从低速开始，GitHub 整理不等于部署验收。

## 日常工作流

```bash
# 从唯一发布基线开始短期开发
git switch main
git pull --ff-only origin main
git switch -c <topic>

# 完成验证后合并回 main，并删除短期分支
git switch main
git merge --no-ff <topic>
git branch -d <topic>
git push origin main
```

涉及策略、状态机、观测/动作维度或真机入口的改动，应在合并前单独记录测试结果和
策略 SHA256；禁止把编译产物、运行日志和本机备份作为发布文件加入提交。
